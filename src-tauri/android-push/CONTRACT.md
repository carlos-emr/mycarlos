Android FCM transport scaffold (default OFF)

This stack is based on PR193 head 9eca8a9757220de844c5e9b525f6bd94f9315696.
Android packaging is generated by `tauri android init`; gen/android is ignored.
The app-local Kotlin bridge is registered only for Android with Cargo feature
`android-push`. There are no frontend controls or renderer command grants for
this transport. The existing Windows notification feature remains separate.

Reviewed platform configuration still needed:

- A Firebase Android client configuration for package `ca.carlos.mycarlos`
  (google-services.json public client configuration, never a service account key).
- A Google Play services device/emulator and reviewed dependency resolution for
  `firebase-messaging:26.0.1`. No Analytics SDK is added; collection and FCM auto-init
  are disabled in the generated manifest. Firebase public resources are generated
  directly, so the Google Services Gradle plugin is not required.
- A Portal after-commit outbox provider implementing the fixed generic template,
  token replacement, expiration, revocation tombstones and invalid-token cleanup.
- A native consent/enrollment owner wiring Policy and the scoped credential below.
  The present transport deliberately has no caller that enables it. Enabling this
  Cargo feature alone neither enrolls a destination nor requests permission.

After generated Android initialization and the existing android:secure hook,
`npm run android:push -- /private/path/google-services.json` copies Kotlin/resources,
adds the messaging dependency and patches the manifest idempotently. The hook fails
on absent/wrong client config or unmanaged messaging declarations. Review generated
output before a guarded `tauri android build --features android-push`. Default CI
is unchanged. Feature-OFF builds reject any residual push sources, manifest
metadata, dependency, icon or client config. Regenerate the generated Android
project before switching profiles; no ON artifact is silently reused by OFF. Do not use this hook in a default build without the corresponding
reviewed feature/profile. No cloud provisioning is performed by the hook.

Native token/event boundary:

1. Explicit user consent starts Policy::opt_in and refreshes OS permission.
   `request_permission` prompts only on demand; retry after observing permission.
2. Native owner verifies the active vault/link, reserves a native-generated
   subscription ID/epoch and atomically persists Policy BEFORE `enable_transport`.
   Kotlin stores only a private transport opt-in, token/generation and bounded
   latest hint. Existing Android backup exclusions apply to these preferences.
3. Serialize transport commands in the native owner and await shutdown/deleteToken
   before re-enabling; run blocking Rust PluginHandle calls off the UI thread.
   Read `snapshot` on every resume/reconnect and after enrollment failure. Token
   rotation increments generation; compare the current snapshot again before
   acknowledging an enrollment. Portal must reject stale generations with a monotonic
   per-destination generation check; a late request must not roll back token rotation. A stale token-fetch callback cannot overwrite a
   newer consent session or an onNewToken event. No destructive event drain is used.
4. Enrollment uses a separately issued, expiring, per-destination/device credential
   limited to create/replace/revoke notification destinations. Provider token and
   credential stay native; neither enters renderer IPC, logs or notification data.
   This credential MUST NOT be a vault unlock key, content-decryption key, document
   pickup credential or reusable signing key. No credential is provisioned/stored
   here, and no enrollment endpoint is guessed or called.
5. Native owner persists Policy opt-out/remove-owner/remove-vault revocations BEFORE
   disabling transport; server must tombstone unknown IDs to defeat late enrollment.
   Revoke with scoped credential; keep pending revocation durable across failures.
   `disable_transport` disables auto-init, clears local token/hint and calls deleteToken.
   Failed delete requires retry. Already in-flight provider notifications can still
   appear until revocation takes effect; generic content is therefore mandatory.

Provider HTTP v1 contract:

Send a notification+data message with fixed notification title `myCarlos` and body
`A new document is available in myCarlos.`. Android channel ID `mycarlos-ready-v1`,
tag `mycarlos-ready`, visibility PRIVATE; no click_action, image, URL, document ID,
patient/clinic text or freeform text. Set only data key `ready_hint`, containing the
existing <=256 byte ReadyHint JSON: version, documents_ready kind, opaque subscription
ID, epoch and positive sequence. Provider must use a stable tag for replacement and
server freshness/sequence controls. The app never copies provider text into a local
notification. Background HTTP v1 notifications are displayed by FCM/OS directly;
local Policy cannot inspect those before display. Server consent/revocation is part
of the display boundary. Foreground callbacks only populate the native inbox. Local generic display requires
Lifecycle::display_foreground with current native owner, consent, enrolled destination,
subscription epoch, OS permission and sequence checks. The native owner holds its
serialization/ownership lock through the synchronous display closure; Kotlin then
rechecks transport enabled, permission and foreground window focus. No callback
displays directly.
Data-only messages set the native reconcile flag opportunistically; they do not
promise a wake, background Rust/webview execution or document collection.

Cold start and warm notification taps capture only ready_hint. Rust decodes it with
ReadyHint::decode; the owner must call Policy::activate against the current native
vault/link after unlock, then navigate to Clinic documents. Never unlock, download,
decrypt or open a payload URL from a hint. Independently reconcile on every normal
resume/unlock/reconnect; lost, collapsed, duplicate and invalid hints are expected.
The persistent reconcile flag is advisory and intentionally remains set in this
scaffold until a future native owner supplies durable reconciliation acknowledgments.
